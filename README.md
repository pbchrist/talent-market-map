# talent-market-map

### → [Open the app](https://pbchrist.github.io/talent-market-map/)

**Every sourcing tool searches the pool you already thought of. This tells you
which pool to search.**

Paste a job description. It works out the capability underneath the job title,
then finds the industries where people build that capability without ever
holding that title — and hands you the searches that find them.

No install, no database, no scraping, no candidate data. It runs in your browser
against a model you choose: your key, or your own local model.

---

## The problem it solves

From the recruiting industry's own writeups on market mapping:

> "the target title is too narrow, so the team misses adjacent titles that
> candidates actually hold"

> "without the map, every sourcing strategy rebuilds the marketplace
> understanding from scratch every time a req opens"

That work is real, valuable, and still done by hand on a whiteboard. Boolean
generation is solved — SeekOut and QSourcer both do one-click Boolean from a JD.
Knowing *where to point the Boolean* is not.

## Example

Input: a Director of Trust & Safety req. Content policy, enforcement tooling,
law-enforcement escalation. Nothing else.

It first names the capability, with the title stripped away:

> Architecting and operating real-time behavioral governance systems that
> translate ambiguous risk into enforceable rules, operational workflows, and
> external stakeholder coordination.

Then finds who builds that, and never calls themselves a Trust & Safety lead:

| Pool | Where | What they call themselves |
|---|---|---|
| Financial Crime & AML Operations | Stripe, PayPal, Coinbase, Chime | Director of AML Operations, Head of Fraud Investigations |
| Cyber Threat Intelligence & IR | CrowdStrike, Mandiant, Cloudflare | Director of Incident Response, Head of Threat Operations |
| Emergency Dispatch & Crisis Response | Everbridge, Life360 | Director of Emergency Operations, Head of Crisis Response |
| Marketplace Abuse & Platform Risk | Airbnb, Etsy, DoorDash | Head of Marketplace Integrity |

Each carries its transfer logic — the concrete reason that background does this job:

> **Financial Crime & AML Operations** — They translated regulatory and risk
> policies into real-time automated enforcement systems, managed high-stakes
> escalations with law enforcement and regulators, and made binding decisions
> under incomplete data at scale.

...plus what to look for on a profile, what rules someone out, and a pasteable
X-ray that needs no LinkedIn seat.

Run the same thing on an autonomous-vehicle simulation req and it returns
real-time VFX, military wargaming, theme-park ride control, and warehouse
robotics. Different field, same machinery.

## Command line

```bash
python -m src.marketmap.cli --title "Director of Trust & Safety" --role jd.txt
```

`--role` takes a file or the text itself. Useful flags:

| Flag | What it does |
|---|---|
| `--graph` | writes an interactive graph of the map beside it |
| `--browse` | drives a real browser through each X-ray and returns the profiles |
| `--search` | opens each X-ray as a real search in your browser |
| `--find` | searches GitHub for people who have actually built this |
| `--brief` | reads each GitHub candidate's career arc |
| `--all` | include the obvious pools as well |
| `--reuse` | load a saved map instead of regenerating |

Maps persist to `maps/`, so the second req in a market inherits the first.

Endpoint is environment-driven:

```bash
export TMM_LLM_BASE_URL=http://localhost:8081
export TMM_LLM_MODEL=your-model
```

## Three design decisions worth explaining

**The model supplies judgement; code supplies syntax.** The model decides which
pools, why they transfer, and who is in them. Every Boolean and X-ray string is
then assembled in `strings.py`. A model asked to emit Boolean will drop an `OR`
or leave a paren unbalanced, and you won't notice until the search quietly
returns garbage. Generated syntax is always balanced because it is never
generated by the model.

**The prompt fights the thesaurus failure.** Ask any model for "adjacent titles"
for a Simulation Engineer and you get Simulation Developer, Simulation
Specialist, Senior Simulation Engineer. That is a synonym list, and it is what
every existing tool already gives you. The prompt forces the model off the title
and onto the underlying capability first, then asks who develops that capability
in industries that never use the word.

**Search runs in a real browser, not a script.** Measured, not assumed: Google
refuses programmatic requests, Mojeek returns 403, DuckDuckGo's HTML endpoint
throttles after a handful, and all nine public SearXNG instances rate-limit. A
real browser is not blocked because it is not pretending. LinkedIn itself is
never touched — it reads a search engine's results page, which is what X-ray
sourcing has always been.

## Honest limitations

- **Small sample.** Validated on a handful of roles, not a benchmark.
- **Signal quality caps result quality.** A pool whose signals are generic
  ("Unreal Engine") returns generic people. The leap comes from specific ones
  (`OpenUSD`, `Golaem`).
- **The pools are a starting point, not a verdict.** A recruiter still has to
  judge whether a transfer argument holds.
- Keep browser search at human volume. It is a tool for working a req, not a
  crawler.
